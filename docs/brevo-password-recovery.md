## Implemented

- POST /api/auth/forgot-password: email and optional accountType (`partner`, default, or `admin`). Only ACTIVE accounts qualify. Uniform generic response before asynchronous account/provider I/O; invalid email is 400, missing service configuration/database is 503 for everyone.
- POST /api/auth/reset-password: token, password, confirmPassword. Both account types use the same endpoint with no duplicate routes. Successful response contains the appropriate loginPath.
- 32 random bytes, SHA-256 storage, 15-minute expiry, one outstanding token/account, 60-second atomic account cooldown. Existing express-rate-limit protects each endpoint at five requests per IP per 15 minutes. Do not broadly relax proxy/IP handling to bypass limits.
- Atomic findOneAndUpdate checks token hash, expiry, recent request and ACTIVE status while changing the bcrypt(12) hash, revoking sessions and unsetting the token. No Mongo replica-set transaction is needed for this single-document operation. Old tokens from the incomplete one-hour flow without a recent request timestamp are not accepted.
- Passwords require eight characters, letters and numbers, maximum 72 UTF-8 bytes (bcrypt limit); confirmation is mandatory. Password changes through the existing profile helper now correctly unset outstanding recovery tokens as well.
- Partner login links to /forgot-password. Admin login links to /forgot-password?account=admin. /reset-password has new/confirm fields, visibility control, loading/error/success feedback and sign-in navigation. Existing brand/components are retained.
- Backend-only Brevo HTTPS service with 10-second AbortSignal timeout, no redirects, no secret/body logging, plain-text and HTML templates. API 201 means provider acceptance, NOT proof of inbox delivery. Provider failure invalidates only the token generated by that request.
- Email links use https://vedaffiliatepvtltd.com/reset-password#token=... . Fragment tokens are intentional: HTTP requests, Nginx access logs and Referer headers do not contain them. An early bootstrap script captures/scrubs the fragment before fonts/scripts load and sets no-referrer. Legacy query tokens are scrubbed too, although an already-supplied query may have reached access logs. Do not enable request-body logging on reset endpoints.
- PUBLIC_APP_URL is required and must be an HTTPS origin without credentials/path/query/fragment; production additionally enforces the canonical VED origin. Incoming Host/Origin headers never construct email links. Recovery API responses are no-store; Express-served reset pages also set no-store/no-referrer. Existing Nginx is untouched.
- No Nodemailer, SMTP server, paid SDK or new package dependency.

Delivery is best-effort in the existing persistent Node process after the generic response. Process termination can interrupt an outstanding email; users can retry after the cooldown. There is no durable email queue or automatic retry worker in this patch. Errors produce only a fixed, credential-free recovery message in backend logs. Monitor these logs and Brevo transactional delivery logs. Daily quota exhaustion/delayed email can cause a link to expire; never extend expiry silently.

## Previously requested lead filters (also retained on this branch)

Admin Leads and Partner Leads now have From Date, To Date, Month, Year and Reset Filters. Shared configuration is Asia/Kolkata (IST, UTC+05:30), labelled on-screen. Existing UTC timestamps remain unchanged. Date-only To Date includes the whole business day via exclusive next-day boundary. Explicit ISO dates with offsets retain their prior instant semantics. Month requires a year; year alone filters the full year; dates and month/year intersect. Invalid/inverted ranges return 400; nonoverlapping combined valid filters return no rows. Reset restores all search/status/campaign/date filters and page one.

Partner list queries enforce the authenticated partner ID; CSV export receives the same date filters and retains mobile masking. Admin visibility/archive policy is preserved. Counts and data share the same backend query before pagination. No records or monetary amounts are rewritten. CSV timestamps stay labelled UTC; calendar selection uses IST. Changed tests/adminPagination.test.ts only updates its state double for new date filters.

## Rollback

Preferred incident response: disable recovery routes/UI in a reviewed VED-only patch while retaining current password hashes, token-consumption guarantees and session-revocation handling. Do not restore the old insecure recovery implementation that logged tokens and accepted one-hour resets. If reverting a full application release is necessary, separately block recovery until the safe implementation is restored. Restore only VED's previous configuration/build as appropriate and reload only that service. Preserve account password changes, revocation timestamps, leads and financial records; never restore an old Mongo snapshot over live user activity. Additive optional recovery fields can remain. Tokens expire naturally; do not bulk edit customer records. No Nginx/DNS rollback is needed because neither was modified.
